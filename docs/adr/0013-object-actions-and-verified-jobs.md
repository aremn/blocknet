# ADR-0013: Объекты взаимодействия, грузовые задачи и проверяемые результаты

Статус: принято, 2026-10-28. Дополняет ADR-0006, ADR-0008, ADR-0010 и ADR-0012.
Заменяет ограничение ADR-0012 на фиксированные 19 инструментов: полнота рабочего сценария
проверяется тестами вместо произвольного ограничения количества.

## Причина

Последний перенос между сундуками не начал ни одного withdraw/deposit: наблюдения давали refs,
действия требовали координаты, а проверка принимала подход к игроку за результат переноса.
Такие планы попадали в библиотеку успешных решений. Увеличение восприятия этого не исправляет.

## Решение

- `use`, `look-in`, `withdraw`, `deposit` принимают либо ref, либо координаты. Смешение запрещено.
  `inspect` разрешает ref без перемещения и без скрытого чтения содержимого. `look-in` возвращает
  только открытый контейнер. Вышедшие из памяти refs требуют повторного наблюдения.
- Чат фиксирует блок под прицелом игрока в момент сообщения. `p#` — отдельная ограниченная
  таблица подсказок текущего сервера, максимум 128 записей. Это не память зрения. Контейнерные
  действия по подсказке всё равно подходят, проверяют достижимость и открывают обычное меню.
- `transfer source destination` — детерминированный навык с начальным составом груза, партиями,
  проверкой вместимости открытого назначения и учётом реально перемещённых компонентов предметов.
  Чужое изменение источника блокирует задачу. Личные количества не отправляются как груз.
- Незавершённый груз хранится в SavedData по UUID: координаты, измерение, остатки, доставка и
  переносимая партия. Повтор с теми же контейнерами продолжает работу; утраченный груз блокирует
  завершение. `job` показывает состояние; `job action=forget` явно оставляет груз обычным инвентарём.
  Это сохранение на штатных точках жизненного цикла, не транзакционная гарантия при аварии ОС.
- Условие `transferred source destination` требует прямого вызова transfer. Подтверждение берётся
  из коррелированного результата вызова, а не из произвольного широковещательного события.
  Поздний результат отменённого вызова не завершает новое поручение.
- Последний критерий плана сохраняется при перепланировании и пересмотре по подсказке.
  `blocked` — допустимый ответ с причиной/вопросом, без фиктивного плана из come. Прозаический
  шаг нельзя подтверждать позицией, атаку — наличием оружия. Полное понимание произвольного
  намерения по-прежнему зависит от модели; это не общий формальный доказатель всех задач.
- Библиотека версии 2 повторяет только прямые цепочки acquire/craft с проверкой инвентаря и без
  missing capabilities. Пространственные refs и старые записи не повторяются автоматически.

## Зрение и просмотр памяти

`debug.memory` требует аутентификации моста, работает на серверном потоке, читает ObservedMap
и последние снимки меню. Скрытые world-state, карта структур и радар в изображение не входят.
Просмотрщик — локальный Node HTTP-сервер с двумя видами: проекция до Y и срез Y. Секрет моста
остаётся на сервере; HTTP допускает только чтение с локального origin. Сохранённый снимок явно
помечается отдельно от живой игры. Цвет — семантический класс, не текстура Minecraft.

## Следующий слой возможностей игрока

`menu` читает открытые слоты, курсор и DataSlots, которые меню синхронизирует клиенту.
`menu_click` использует обычные клики/кнопки меню, проверяет containerId, валидность меню и
интервал трёх тиков. Это общий слой для обычных машин. Клиентские действия, особые сетевые
терминалы и автокрафт требуют адаптеров, когда не представлены обычными слотами/кнопками.
Серверный `plan` доступен модели для дерева поддержанных рецептов; он не заменяет все категории JEI.

`obtain` сначала использует уже увиденную руду. При расчёте дефицита нельзя производить сырьё
через собственный цикл упаковки/распаковки: при отсутствии packed-item сообщается исходный
дефицит. Строгий проход по имеющемуся инвентарю продолжает использовать распаковку, если она
действительно возможна. Изменение остаётся в LGPL-модуле crafting с исходными заголовками.

## Проверки и границы

GameTests проверяют refs, отдельную подсказку игрока, реальные меню и прогресс печи,
многократные ходки, остановку/возобновление, потерю груза, чужое опустошение источника и
неизменность памяти при запросе снимка. Сквозной сценарий добывает увиденную руду, плавит,
крафтит и кладёт результат в сундук. Подготовленные инструмент, топливо и часть материалов
в этом сценарии заданы явно; отдельные старые тесты проверяют подготовку инструментов с нуля.

Наличие этого слоя не означает, что агент уже умеет произвольные технологические цепочки,
автокрафт сетей или строительство кабельной схемы. Эти возможности принимаются отдельно
после адаптера и сквозного теста на реальном содержимом сборки.
